# Rust ↔ C++ ↔ Python bindings (`dfg_da_c` / `dfg-da-sys` / `dfg-da` / `dfg-da-py`)

A bare-minimum Cargo workspace that calls this repo's C++ single-cluster LBP
through a **C API**, with raw FFI generated by **bindgen** and Python bindings
generated by **pyo3 + maturin**. Modeled on `~/kalib-rs`.

## Layout

| path | role |
|---|---|
| `dfg_da_c/` | C-API wrapper (C++): opaque handles + `extern "C"` funcs over `dfg_da::lbp::lbp_single_cluster`. Built as a **static** lib by CMake (Eigen only — no GTSAM). |
| `dfg-da-sys/` | Raw FFI. `build.rs` runs CMake then `bindgen` (→ `OUT_DIR/bindings.rs`); `links = "dfg_da_c"`. |
| `dfg-da/` | Hand-written safe wrappers (`Hypotheses`, `LbpOutput`, `lbp_single_cluster`) with RAII `Drop`. |
| `dfg-da-py/` | pyo3 `cdylib` exposing `lbp_single_cluster_bethe(...)`; built with maturin. |

The C API compiles `src/hypothesis.cpp` + `src/lbp.cpp` directly (same GTSAM-free
set as the `py_dfg_da` Python extension), so it has no dependency on the pybind11
build or GTSAM.

## Build & test

Prereqs: `cargo`/`rustc`, `cmake` (`~/.local/bin` here), system Eigen
(`/usr/include/eigen3`), a C++17 `g++`.

```bash
# Rust library + FFI + safe layer, plus the C++/C-API cross-path unit test
cargo build -p dfg-da
cargo test  -p dfg-da

# Python module into the root .venv
.venv/bin/pip install -r requirements-dev.txt      # adds maturin
cd dfg-da-py && ../.venv/bin/maturin develop && cd ..
```

Verify the Rust path matches the proven `py_dfg_da` C++ extension bit-for-bit:

```bash
.venv/bin/python - <<'PY'
import numpy as np, py_dfg_da, dfg_da_py
R = np.array([[0.30,0.10,0.00,-np.inf],[0.05,0.40,-np.inf,0.00]])
h = py_dfg_da.hypothesis.Hypotheses([py_dfg_da.hypothesis.Hypothesis([1,2],0.0)])
z_cpp = py_dfg_da.lbp.lbp_single_cluster(np.asfortranarray(R), h, 300).bethe_pseudodual_normalization_constant()
z_rust = dfg_da_py.lbp_single_cluster_bethe(R.flatten().tolist(), 2, 4, [([1,2],0.0)], 300)
assert np.isclose(z_cpp, z_rust); print("match:", z_cpp)
PY
```

## Extending

Add a C function in `dfg_da_c/include/dfg_da_c/lbp.h` + impl in `src/lbp_c.cpp`
(keep the `dfg_`/`Dfg` prefixes so bindgen's allowlists pick them up), then a safe
wrapper in `dfg-da/src/lib.rs` and, if needed, a `#[pyfunction]` in
`dfg-da-py/src/lib.rs`. `bindgen` regenerates automatically.

> Note: `maturin develop` warns about `patchelf` for rpath — harmless here because
> `dfg_da_c` and `libstdc++` are statically/system-linked. `pip install patchelf`
> silences it if you build a distributable wheel with `maturin build`.
